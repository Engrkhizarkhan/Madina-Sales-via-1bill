# Counter usability and passenger history — 28 October 2026

The seat booking workspace now keeps compact Booked, Reserved and Available totals below the passenger card. Sidebar rows, roster rows and register cells use less space. Existing receipt/token printing remains unchanged.

Female seats are pink, with lighter shading and an R marker for reservations. Online seats use yellow; female online seats retain pink with a yellow W marker. Clicking any occupied seat opens its passenger actions. Unpaid online reservations can be edited or removed; paid tickets retain the audited refund workflow.

Every route exposes all non-retired fleet layouts, deduplicated by service and capacity (currently Standard Plus 49, Sleeper 35, Executive 41 and Executive 44). Select the type, enter the vehicle and actual departure, then Save bus / time. This changes only the dated departure. Different seating plans are rejected while any confirmed or reserved seats remain. Known vehicle numbers must match the selected layout and be ready; a new vehicle number inherits that layout. Vehicle conflicts and concurrent edits remain checked. Unsaved departure edits disable new ticket/reservation submission. A changed assignment invalidates locally selected seats, and the API rejects counter submissions carrying stale vehicle/type/time details.

Passengers is a dedicated directory with name, phone, CNIC/passport, gender, journey, boarding point, vehicle/type, seat, source, payment and refund details, search, status filters, CSV export and access to the departure. It includes closed records. Date filters are inclusive and default to all history; dashboard defaults to today. Reversed ranges display an error and no records.

Travel-date ranges filter dashboard ticket counts, passengers, bookings, reservations, roster history and finance. Today's departure panel is explicitly separate from historical ticket statistics. Finance groups sales and their associated refunds by travel date; costs use expense dates. Expense history has its own expense-date range. Removed the expense query's silent 1,000-row truncation so date-filtered totals and exports cover the entire stored history.

Validation: production build, ESLint, Node syntax checks, 80 API integration checks, 35 counter workflow checks, and 8 layout/date tests. Browser checks against an isolated MySQL database cover female ticket/reservation colors, online female markers, editing and removing online holds, all four bus-type choices, unsaved departure blocking, date filters, passenger search, and desktop/mobile layouts. No production test bookings are created. QA screenshots are stored locally in ignored output/playwright/oct28/.

No schema migration or dependency changes. Deployment uses a database/source/web backup, Git fast-forward, prebuilt static assets, and the existing Madina Express PM2 process. Other services are not restarted.
