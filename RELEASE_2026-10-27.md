# Counter workspace update — 27 October 2026

The Seat booking page now contains route/date/service selection, departure times, manual vehicle/time changes, passenger entry, seat management and the voucher summary. A departure can be opened in another tab and its link preserves the selected date and schedule.

- Light blue seats are reservations; dark blue seats are confirmed tickets. Selecting an occupied seat opens payment, edit, print and cancellation/refund actions on the same page.
- Every new seat has its own booking ID and ticket/reference number. Multi-seat selections are saved atomically and discounts are divided in cents. Holds create no sale or printable ticket; payment confirmation issues the ticket.
- Each paid seat prints a compact 80 × 140 mm passenger receipt followed by a separate 80 × 75 mm conductor token. Urdu and the existing monochrome typography are retained. Legacy multi-seat records stay intact, but their reprints use separate slips with apportioned amounts.
- Manual vehicle numbers create/reuse a fleet record with the selected layout; changes apply to the dated departure and its active tickets. Closed departures and incompatible layouts are protected.
- The voucher holds manual crew, percentage/additional commission, refreshments, terminal expense, toll, miscellaneous expense and driver handover. Commission uses collections net of refunds. A voucher save updates one linked expense and appends only the difference to the audited financial ledger. Driver handover is shown separately and is not counted again as an operating expense.
- Printing a voucher requires a saved summary matching current net collections. The passenger/CNIC sheet is available directly; the duplicate Bus Detail option was removed. Finance includes operating costs and net after expenses.
- Counter users may issue audited refunds; finance and user administration remain protected.

No schema migration or changes to existing bookings are required. New voucher metadata uses the existing departure snapshot and expenses tables. The production Node API is the supported backend; the archived PHP implementation does not contain these features.

Validation: existing API integration suite, dedicated isolated-database counter workflow tests, seat/print helper tests, TypeScript production build, ESLint, and browser checks covering two-seat sales, holds, cancellation, refunds, manual bus/time, voucher save/re-save, reload persistence and mobile overflow. Printed PDFs were inspected for separate pages and readable Urdu. Physical cutting remains the printer driver's cut-after-page setting.

Run `npm run test:counter` only against an isolated database whose name contains `test` or `qa`, with `TEST_API_URL` pointing to its Node API. Test configuration must never point at production.
